# Topic Radar — мониторы небольших каналов

Установка: [Windows / Python](README_LOCAL.md) или [Docker / HTTPS](README_SERVER.md).

## Как пользоваться

1. Войдите в сервис. Учётная запись владельца — `admin`; пароль задаётся при установке.
2. В **Настройках** добавьте YouTube API key, понятное название и Google Cloud project ID.
   Первый ключ выбирается автоматически. Секрет не показывается в списках или экспортах.
3. Нажмите **Новое исследование**, введите запросы и выберите русский или английский.
   Остальное заполнено: до 10 000 подписчиков, 7 дней, до 100 результатов на запрос.
   Выберите формат: **Все форматы / Shorts / Обычные видео**.
4. Выберите **Наблюдать регулярно** либо **Посмотреть один раз** и запустите.
   Мониторы появляются на главной, разовые исследования — в истории.
5. Откройте дашборд: сигналы роста, небольшие каналы, график и таблица.
   **Обновить рост** получает счётчики известных видео без нового поиска.
6. **Настройки и управление** содержат расписание, запросы, фильтры, выбранный ключ,
   полный поиск и поиск новых публикаций. Изменение настроек не обращается к YouTube.
7. Копирование видимых строк учитывает фильтры; CSV/JSON/Markdown содержат весь список.
   Заметки и сохранённые видео доступны как раньше.
8. **Удалить исследование** доступно в истории, на карточке монитора и в его настройках.
   Оно исчезает со всех основных списков, мониторинг выключается, задания в очереди
   отменяются. Уже отправленный запрос может завершиться; новые запросы остановятся.
   **История → Удалённые** позволяет восстановить исследование на паузе.
   Общие данные видео/каналов и избранное сохраняются, срок API-данных остаётся 28 дней.

Периоды поиска: сутки, 2 дня, неделя, 2 недели, месяц, 3 месяца, полгода, год.
Глубина на запрос: 50 / 100 / 200 / 500. YouTube может вернуть меньше; ID объединяются.
При смешанном поиске страницы делятся между популярными и свежими публикациями.
Окно в сутки — 24 часа на момент поискового ответа; при использовании кэша показывается
исходное время. Накопленная история может содержать более старые найденные видео.
Язык — предпочтение YouTube, не строгий фильтр по озвучке каждого ролика.

## Два интервала наблюдения

- Поиск и широкий пересмотр всех ID: каждые 4 / 6 / 12 / 24 часа.
- Замеры лидеров: каждые 30 / 60 / 120 минут.
- Активный топ: 50 / 100 / 200 / 500 малых каналов, один лидер на канал.
  Новые малые кандидаты получают повторный замер дополнительно к топу.
- Пауза запрещает следующие автоматические запуски. Уже выполняемый запрос завершается;
  его можно отменить отдельно. Несколько исследований выполняются последовательно.

Число исследований не ограничено отдельным продуктовым лимитом. Практические ограничения —
квота, объём SQLite и время последовательного исполнителя. Сервис должен быть запущен.

## Что показывают данные

### Метаданные, реакции и форматы

Кнопка **Подробнее о видео** открывает описание, хэштеги из названия/описания,
теги автора, длительность, язык, дату публикации и историю просмотров, лайков и
числа комментариев. Можно скопировать карточку вместе со всеми доступными замерами.
Раскрываемый JSON содержит полный публичный ресурс `videos.list`: snippet,
statistics, contentDetails, status, topicDetails, recordingDetails, liveStreamingDetails,
localizations, paidProductPlacementDetails и player, если YouTube их вернул.
Закрытые поля владельца и тексты комментариев не запрашиваются. Отсутствующее
значение показывается как «—», а не ноль. Карточка показывает разницу реакций
между двумя последними фактическими замерами; отрицательное изменение сохраняется.

Метаданные фиксируются при каждом получении и доступны в JSON/внешнем API.
CSV и Markdown включают описание, теги, формат и счётчики. Срок хранения API-данных
остаётся **28 дней**. Старые записи не подменяются сегодняшними: для получения
описаний и тегов в новом снимке нажмите **Обновить рост**. В существующей старой
истории эти поля могли отсутствовать. Все счётчики относятся ко времени ответа API,
не к моменту открытия страницы. История карточки ограничена временем её снимка.

YouTube Data API не предоставляет `isShort`. **Shorts · оценка** — вывод по
длительности и явным пропорциям player из API: квадратные/вертикальные до 3 минут
для публикаций с 15.10.2024 (до этой даты — до 60 секунд). Есть исключения,
например исторические публикации официальных музыкальных каналов, поэтому это
оценка, а не подтверждение YouTube. Для роли **Возможный Shorts** длительность
подходит, но пропорций/даты нет; такие кандидаты тоже входят в исследование Shorts.
Эскизы и хэштег #shorts не считаются доказательством формата. Трансляции исключены.
**Обычные видео** включают горизонтальные короткие ролики и длинные видео.
Неопределённый формат доступен в общем списке и отдельном фильтре таблицы.

Поиск Shorts использует `videoDuration=short` (API: короче 4 минут), затем сервис
уточняет формат по метаданным. Для обычных видео используется общий поиск с
последующей фильтрацией. Данные обрабатываются пакетами до 50 ID без дополнительных
поисковых вызовов; набор публичных полей не увеличивает стоимость `videos.list`.
Выбор формата распространяется на фильтры, рейтинг, повторные замеры и расписание.
После изменения формата выполните полный поиск, чтобы расширить найденную выборку.

Источники: [публичные поля видео](https://developers.google.com/youtube/v3/docs/videos),
[поиск по длительности](https://developers.google.com/youtube/v3/docs/search/list),
[правила Shorts](https://support.google.com/youtube/answer/15424877?hl=en).

Первый срез — кандидат, не измеренный рост. Для роста нужны два свежих ответа с интервалом
от 30 минут. Рейтинг нормируется на число подписчиков с нижней границей 1 000; точная
формула и критерии сигнала доступны в настройках дашборда и `app/signals.py`.

График показывает до пяти лидеров текущего списка. Точка — фактический измеренный темп;
после первого повторного замера будет только одна точка на серию. Для линии нужен ещё
один замер. По каналам и темам показана медиана наблюдаемых видео по каналам в 10-минутных
окнах, не весь трафик канала. Исторические снимки не используют последующие наблюдения.
Есть текстовая таблица значений под графиком.

Совпадение темы требует разных небольших каналов. Значения просмотры/подписчики не являются
сравнением с обычными публикациями автора и не гарантируют успех похожего ролика.
API может возвращать статистику видео, которое нельзя воспроизвести у конкретного зрителя;
полная проверка воспроизведения и региональных ограничений в эту итерацию не входит.

### Каналы, избранное и ручные замеры

Раздел **Каналы** собирает авторов найденных видео. Можно искать по названию,
выбирать каналы до 10 000 подписчиков, добавлять в избранное и сортировать по
подписчикам, просмотрам или их скорости роста. Нажмите название канала в таблице
видео, чтобы открыть его отдельную страницу.

Карточка хранит описание, публичные поля YouTube, общие просмотры канала, число
подписчиков и публичных видео. График и таблица показывают реальные замеры;
кнопка копирования включает все доступные данные и историю. Ниже — видео канала,
которые уже найдены нашими исследованиями, и ваша заметка.

**Обновить сейчас** получает только выбранный канал. **Обновить это видео** в карточке
получает только выбранное видео. В исследовании это создаёт новый снимок с сохранением
остальной выборки; в сохранённом и на странице канала обновляет текущие данные объекта.
Старые снимки исследований не переписываются. Обновления выполняются последовательно
тем же worker; повторный клик во время одинакового задания не создаёт дубликат.

Для видео и каналов показываются изменение **+/−**, процент и средняя скорость:
`(новое значение − предыдущее значение) / прошедшее время в часах`.
Нулевой результат означает отсутствие изменения, «нет сравнения» — отсутствие пары
значений. При нулевой базе процент не вычисляется. Интервал короче пяти минут явно
помечен: такой темп может колебаться. Рейтинг тренда по-прежнему требует интервала
не менее 30 минут; частое нажатие кнопки не превращает минутный всплеск в сигнал.

YouTube округляет подписчиков до трёх значащих цифр: их прирост приблизительный.
Общие просмотры канала включают все форматы, не только Shorts из исследования.
Канал обновляется при фактическом `channels.list` в исследовании (кэш до 24 часов)
или вручную; 30-минутный мониторинг видео не означает замер всего канала каждые 30 минут.
Старые каналы получили сохранённую историю подписчиков, но отсутствующие исторические
просмотры/число видео не выдумываются: первый ручной замер создаёт для них базу.
[Описание публичных счётчиков YouTube](https://developers.google.com/youtube/v3/docs/channels#statistics).

В **Сохранённом** есть кнопка обновления всех избранных видео и ссылка на избранные
каналы. В **Каналах** можно обновить все избранные каналы. Заметка без закладки
не включает объект в массовое обновление. Перед обновлением можно выбрать API-ключ.
Используются пакеты до 50 ID за одну общую единицу API, поисковых запросов нет.
Пропавшие из ответа объекты не обнуляются; интерфейс сообщает о неполном обновлении.
Все публичные API-данные и замеры хранятся 28 дней. Закладки и пользовательские заметки
сохраняются отдельно; устаревший избранный объект можно запросить заново.

## Несколько ключей и квоты

Каждое исследование привязано к одному ключу. В настройках виден расход ключа и суммарный
расход ключей с одинаковым project ID. Для перенесённого старого ключа проект изначально
обозначен `default`; укажите настоящий project ID перед добавлением других ключей того же
проекта. YouTube Data API не сообщает его через используемые методы.

Счётчики являются локальной оценкой. Достижение 100 поисковых / 10 000 остальных единиц
само по себе не блокирует запрос. После реального quotaExceeded соответствующий бюджет
проекта ждёт сброса в Pacific Time. Исчерпание поиска не блокирует доступные замеры по ID.
Учёт других приложений виден только в Google Cloud; неудачные попытки локально считаются
консервативно. Смена имени проекта не снимает полученный запрет на оставшуюся часть суток.

Автоматической ротации разных проектов для обхода квоты нет: это запрещено
[правилами YouTube](https://developers.google.com/youtube/terms/developer-policies-guide).
Для роста объёма используйте экономное расписание, кэш и
[официальное увеличение квоты](https://developers.google.com/youtube/v3/guides/quota_and_compliance_audits).
Ключи одного проекта делят [лимит проекта](https://developers.google.com/youtube/v3/getting-started).

## Вход и внешний API

Для нового локального экземпляра: `python -m app.local_setup`. Команда создаёт
`data/local-auth.json` с хэшем пароля и один раз показывает случайный пароль `admin`.
Повторный запуск не меняет существующий пароль. Перезапустите приложение. YouTube-ключи
остаются в Windows Credential Manager. Существующие данные не удаляются.

Серверный Docker-режим: [README_SERVER.md](README_SERVER.md). Там используются Secure cookies,
HTTPS через reverse proxy и отдельный серверный секрет Fernet. Локальный режим слушает
только loopback и использует HTTP-cookie без Secure. Пароли/ключи не входят в исходники.

В **Настройки → API для MCP Hub** создайте личный токен. Он показывается один раз;
сохраняется только SHA-256. Выберите чтение или чтение с запуском, срок по умолчанию 90 дней.
Токен можно отозвать немедленно. Передавайте `Authorization: Bearer <token>`.
Токен не работает на административных endpoints с YouTube-секретами.

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/api/v1/me` | Проверить доступ |
| GET | `/api/v1/credentials` | ID и названия подключений, расход; без секретов |
| GET/POST | `/api/v1/research` | Список / создание и первый запуск |
| GET | `/api/v1/research/trash` | Удалённые исследования своего пространства |
| DELETE | `/api/v1/research/{id}` | Убрать исследование в корзину и остановить мониторинг |
| POST | `/api/v1/research/{id}/restore` | Восстановить без запуска мониторинга |
| GET | `/api/v1/research/{id}` | Актуальный результат |
| GET | `/api/v1/research/{id}/videos/{video_id}` | Метаданные видео и история счётчиков до времени актуального снимка |
| POST | `/api/v1/research/{id}/actions` | `refresh`, `repeat`, `append` |
| PUT | `/api/v1/research/{id}/schedule` | Расписание и пауза |
| PUT | `/api/v1/research/{id}/config` | Настройки без API-запроса |
| GET | `/api/v1/research/{id}/chart` | Серии графика, `kind=videos/channels/topics` |
| GET | `/api/v1/entities/channels` | Каналы вашего пространства, счётчики и последние изменения |
| GET | `/api/v1/posts` | Общий каталог видео: страницы, поиск, фильтры, сортировка |
| GET | `/api/v1/entities/{videos\|channels}/{id}` | Текущие данные объекта и история |
| PUT | `/api/v1/entities/channels/{id}/note` | Закладка `favorite` и заметка `text` |
| POST | `/api/v1/entities/{videos\|channels}/refresh` | Обновить `ids` либо `favorites: true`, без поиска |
| GET | `/api/v1/entities/jobs/{id}` | Статус, число обновлённых объектов и расход задания |
| GET | `/api/v1/openapi.json` | OpenAPI-схема |

Пример создания (все остальные параметры имеют значения по умолчанию):

```json
{"config":{"seeds":["новые фильмы"],"language":"ru"},"monitor":true,"request_id":"unique-create-123"}
```

Для Shorts добавьте `"video_format":"shorts"` в `config`; другие значения —
`"all"` (по умолчанию) и `"videos"`. Поля `video_format`, `format_reason` и
`shorts_candidate` результата объясняют определение формата конкретного видео.

Повторите тот же `request_id` при повторной доставке одного действия; для нового действия
создавайте новый ID. Ответ содержит ID операции; получайте результат через API списка/исследования.

Обновление объектов принимает необязательный `credential_id` и `request_id`; `ids` и
`favorites: true` взаимоисключающие. Ответ содержит ID задания. Чтение его статуса не
тратит YouTube-квоту. Для записи нужен API-токен с правом `write`.

Миграция 004 добавляет `app_users`, владельцев исследований/ключей/токенов. Сейчас доступен
только администратор. Полная поддержка нескольких пользователей (регистрация, роли,
изоляция заметок и интерфейс администрирования) требует отдельной итерации.
Миграция 005 добавляет историю каналов, связи объектов с владельцами, заметки каналов
и очередь точечных обновлений. Права внешнего API проверяются по владельцу объекта.
Миграция 006 добавляет отдельную таблицу корзины. При откате к старому коду
скрытые исследования снова видны, но их расписания остаются выключенными.
Внешние клиенты и MCP-шлюзы могут использовать HTTP API; отдельного MCP-сервера нет.

## Посты и навигация по спискам

«Посты» — все сохранённые видео и Shorts вашего пространства, без повторов по ID.
Показатели берутся из последнего сохранённого ответа; подробное описание, теги,
исходный JSON и история доступны через кнопку карточки. Из неё можно обновить
одно видео, сохранить заметку или добавить его в избранное. Каталог включает
видео из удалённых исследований до истечения обычного срока хранения в 28 дней.

Поиск учитывает название, канал, описание, теги и хэштеги. Фильтры: исследование,
формат, избранное и небольшие каналы до 10 000 подписчиков. Для последнего фильтра
нужны сведения о канале не старше суток. «Shorts и кандидаты» включает видео,
подходящие по длительности, даже если API не сообщил пропорции.

В постах, каналах, списке исследований и результатах исследования есть страницы
по 20, 50 или 100 записей. Навигация находится сверху и снизу. Поиск и изменение
фильтра возвращают на первую страницу. В постах, каналах и списке исследований
параметры сохраняются в URL — ссылку можно открыть повторно.

Сортировка применяется ко всему отфильтрованному списку до разбиения на страницы.
Направление переключается отдельной кнопкой; в таблицах также работают заголовки
числовых столбцов. Неизвестные показатели остаются внизу в обоих направлениях.
«Копировать страницу» копирует показанные строки; экспорт исследования CSV / JSON /
MD по-прежнему содержит весь список. Чтение, фильтрация и сортировка не обращаются
к YouTube и не расходуют квоту.

API каталога принимает `page` (от 1), `per_page` (1–100), `q`, `research` (ID
исследования), `scope` (`all`, `small`, `favorites`), `format` (`all`, `shorts`,
`video`, `unknown`), `order` (`asc`, `desc`) и `sort` (`observed_vph`, `views`,
`likes`, `comments`, `views_per_subscriber`, `published_at`, `fetched_at`, `title`,
`subs`). Ответ: `items`, `total`, `page`, `per_page`, `pages`. По умолчанию —
20 записей, измеренный прирост по убыванию. Номер за последней страницей
ограничивается последней доступной; пустая выдача имеет `page=1`, `pages=1`.
